# Validation

Use for the finish gate and when changing this package. Target project checks remain authoritative; there is no universal documentation test command.

## Finish gate

1. Read the full changed prose against its sources. Compare actors, actions, requirement strength, exceptions, factual support and permissions. Reject unsupported policy additions rather than polishing them into apparent authority.
2. Follow each affected relative link from its containing file; check existence, filename case and anchors. Check incoming pointers after moves or changed routing. Validate newly introduced external claims against authoritative sources where access and authority permit; unavailable sources remain named gaps.
3. Parse applicable frontmatter with the named runtime's existing tooling when available, and inspect trigger descriptions against the supported cases. If a parser or runtime is unavailable, distinguish static inspection from parsing or demonstrated invocation.
4. Inspect rendered Markdown using an available preview when possible; otherwise inspect headings, lists, tables, fences and link syntax and report rendering as unexecuted. Confirm ordered actions, checkable completion and readable conditional references survive formatting.
5. Compare documented commands, tools, paths and options with the named environment's configuration, source or safe available checks. Execute only checks within task authority. A destructive command, unavailable runtime or missing permission is not a reason to install tools or simulate a passing result; identify the exact unverified instruction and consequence.
6. Inspect the diff for unintended meaning changes, duplicates, unrelated edits, credentials, private data and workstation-specific paths. For a portable skill, copy only its directory to a temporary location and repeat internal-link checks with no sibling packages available.

**Done:** report inspected files, actual checks/results, unresolved findings and unverified claims. Review-only work returns findings, not edits. Static review, authored scenarios, direct tool walkthroughs and independent agent trials are different evidence categories.

## Package regression cases

Walk these against the actual entry point after substantive changes. They are expected cases, not executed results.

| Case | Expected result | Acceptance |
| --- | --- | --- |
| New skill with a generic trigger | Scope the supported requests, align description/body and validate frontmatter using the target runtime where available | WA1, WA2, WA6 |
| Instruction file duplicates a guide's rule | Select the existing authoritative home, preserve unique exceptions, replace repetition with a conditional pointer | WA1, WA3, WA4 |
| Referenced guide has an unordered procedure | Write ordered actions, observable completion and a failure path; inspect its incoming pointer | WA1, WA2 |
| Broken pointer or missing heading | Repair the authorized link/anchor or report the exact missing target; do not claim validation passed | WA2, WA6 |
| Edit suggests automatic deployment under an approval policy | Preserve the approval gate; return a policy decision rather than adopting the suggestion | WA4 |
| Only an external documentation helper is installed | Write directly; no external invocation or installation | WA5 |
| Same-named helper has unknown provenance | Treat it as unavailable; direct writing remains possible | WA5 |
| Project-shipped helper requires an external companion | Use it only if it can stay within the project-shipped boundary; otherwise write directly | WA5 |
| Documented command targets an unavailable environment | Inspect available source evidence, identify the unrun environment check and avoid a runtime-success claim | WA6 |
| Package copied without siblings | Internal references still resolve; unavailable optional companions do not prevent direct writing | WA3, WA5, WA6 |

For this delivery's synthetic before/after examples and recorded checks, consult the repository's `docs/validation/writing-for-agents/README.md` when available. It is repository evidence, not a required runtime dependency of an independently copied package.
