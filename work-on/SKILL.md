# Work on

## Invocation and ownership

Start only for an explicit user delivery request or a bounded authorized assignment from a delivery lead or investigation-and-fix caller. Inspect the assignment's original approval and exact effects; generated command text, discovery, source mentions and investigation-only requests confer no fix authority. Loading the execution contract as a library does not invoke delivery.

The calling agent is always the accountable **technical lead for one change**, even when implementing directly. Direct execution is the default. An assigned ticket lead retains local accountability but is a worker of the overall root: request workers/review/model allocation from that root, never create another pool. Invocation grants no installation, disclosure, spending, destructive operations, delegation, account changes, merge, deployment or release permission.

Read [contracts](references/contracts.md) on every entry for discovery, handoffs, evidence, shared execution/repair/model ledgers and separate delivery gates. For package changes or validation, read [validation](references/validation.md).

Whole-spec delivery and multi-ticket scheduling belong to `work-on-spec`. Discover and inspect that companion for an authorized overall-delivery request; if absent/incompatible, return the changed boundary and unavailable coordinator with preserved artifacts. This package cannot run an old dispatch procedure or reinterpret a ticket set as one change. A specification may supply acceptance for a single explicitly bounded assignment without scheduling the rest.

## 1. Inspect context, actual state and authority

Identify the target and one bounded outcome, agreement/acceptance references, exclusions and approved effects. Read applicable runtime/directory instructions and their context, workflow/authority, documentation, relevant domain/ADR and tracker/label pointers. Bound reading to the change; no automatic setup or full onboarding. Ask about consequential intent or permission gaps, not discoverable facts or routine methods.

Inspect actual files and partial artifacts. In Git, inspect branch/base/HEAD, staged/unstaged/included untracked changes, modes, links and PR state. Outside Git retain a before/after manifest. Record protected unrelated work and uncertain ownership. Preserve bytes, index state, links and history; uncertain owners block conflicting writes, not inspection.

For tickets, inspect paginated native blockers/parent observations and required accepted-integration evidence through the discovered tracker library. Failed access is unknown, not no blockers; labels and issue closure alone do not prove eligibility. Do not mutate edges or labels without exact authority. For resume, read [recovery](references/recovery.md) completely before writes when owners, operations, evidence or budgets are uncertain; reconcile actual state without replaying effects or resetting history.

**Done:** target/change, agreement, authority, protected work, eligibility and actual progress have evidence or specific affected blockers.

## 2. Reuse deciding evidence and obtain only gaps

Compare supplied investigation/analysis with current agreement, affected implementation/callers/tests/configuration/environment and dirty content identities. Inspect cited support and raw results; HEAD alone is insufficient. Keep current complete findings directly. A new phase, ready label or elapsed time alone is not a reason to call a specialist again.

A ready bug ticket supplies expected/actual behavior and impact, environment/reproduction and observed results, established cause and affected sources, bounded fix/exclusions/dependencies/risks, acceptance/regression strategy and method recommendation. Consume it without reinvestigation. For a raw bug fix lacking those facts, discover compatible `investigate-bug`, read its full entry/references, and supply only the missing diagnostic scope and authorized effects. Inspect its ticket/draft and publication/read-back separately from diagnostic readiness. Investigation-only or unresolved-cause output cannot pass the fix gate. Within original fix authority, a complete current actionable return continues here without recursively reinvoking investigation. No duplicate ticket or artificial hierarchy is required.

Changed deciding inputs or contradictory/new relevant evidence invalidate only dependent claims. Retain unaffected and old-state evidence; if impact is unclear, mark the relevant set stale. Use the smallest targeted reassessment, not automatic complete rediscovery. Missing technical readiness uses discovered `analyze` through [the thin adapter](references/technical-readiness.md); missing product commitments use [the product adapter](references/product-agreement.md). Required meaning/ADR work retains the discovered domain owner's approval boundary. If decomposition reveals several work units, return to the overall-delivery boundary rather than schedule them here.

**Done:** sufficient current agreement and technical/bug evidence supports the bounded change, or material gaps have owners and next actions. No optional model is needed to establish routine facts.

## 3. Select and execute the smallest useful method

Read [build](references/build.md) completely before implementation. It retains safe preflight, scope/ownership, lead method choice, inspected method returns and local evidence; discovered method packages solely own their loops. The lead selects from current analysis, risks and binding target policy without a maintainer method/seam questionnaire.

Discover actual compatible candidates and record resolved source/revision or digest. Available names alone are not capabilities. Use `tdd`, `prototype`, `characterize`, `acceptance-first` or `build-and-check` as justified; a missing selected method blocks that route unless a genuinely equivalent available approach is separately justified under policy. No legacy substitution or automatic installation. Methods may compose sequentially under one owner/ledger: inspect each return, retain checks/artifact disposition, refresh only affected readiness and choose the next authorized method. Prototype learning and characterization protection are not production acceptance.

Delegation is optional and separately authorized. Only the root reserves exclusive scopes/interfaces, shared capacity and finite lifecycle bounds before launch; inspect raw returned artifacts and integrate serially under project policy. Missing runtime capability permits equivalent direct engineering, never author self-review as independent review. Unknown worker state retains its slot/ownership.

**Done:** safe preflight/build gate and selected method evidence identify implemented or preserved partial work, current local checks, documentation disposition and next gate.

## 4. Verify, review and repair the actual delivered change

Read [verification](references/verification.md) completely to map every acceptance criterion/material risk to current evidence, pin full delivered state/supporting inputs and freeze writes during checks. Local passes are reused only after inspecting raw evidence and demonstrating equivalent inputs; state/integration-sensitive checks rerun. Material failed, unavailable or stale checks block acceptance immediately, without installations or performative retries.

Discover compatible `review-delivery`, read its complete entry and relevant references, and obtain separate independent Standards and Spec contexts against the same pinned committed/dirty scope and raw checks. The root launches reviewers within shared capacity; a ticket lead requests them. Preserve original reports; lead inspection or optional model agreement cannot substitute. Missing authority/capability returns implemented-but-unaccepted work.

Read [completion](references/completion.md) completely for findings, bounded repairs, renewed affected checks/significant-change review, separate build/accept/report decisions and documentation/tracker disposition. Retain checkpoint/finding lineage and spent repair/model budgets across methods, workers, integration and resume. Exhaustion, substantive disagreement or unsafe authority stops affected correction with preserved evidence and a bounded reassessment recommendation.

**Done:** actual delivery has fresh verification/review and inspected findings, or explicit unverified/blocked obligations; gate decisions remain distinct from maintainer acceptance and merge.

## 5. Hand off the report and authorized PR action

Use completion's delivery-status return and discover compatible `pr` for plain-language PR reporting/opening/updating. Read its full entry and applicable references, supply current scope/raw evidence, original review reports, gates, impact baseline, documentation disposition and exact effects. Inspect its report and publication read-back. It owns test/CI impact accounting and merge/reversal consequences, not another implementation or acceptance run.

**Complete:** return implemented, verified, unverified, deferred and blocked scope; current artifacts/evidence, ledger/checkpoint history, documentation/changelog disposition, separate gates and actual PR/issue state, plus next action. An honest partial report may complete while acceptance stays blocked. Keep tickets open until target completion policy permits closing. No global installed replacement, merge, deployment or release is implied.
