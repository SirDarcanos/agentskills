# Optional background research

Read only when considering background delegation. The calling agent remains accountable for scope, source checking and return quality.

1. **Check authority and capability.** Delegation needs current request/project permission, authorized disclosure to the worker and a runtime with finite lifecycle bounds and separately inspectable source/results. Direct research is the default when equivalent and allowed. If background-only execution is required, missing capability blocks that route. Do not launch merely because the runtime exists.
2. **Resolve conditional coordination.** Discover `work-on` through the catalog or an approved package location; inspect its documented library pointer and read the conditional coordination reference, not the unrelated delivery procedure or universal policy contract. Check it against the project's authority/restrictions and this assignment's lifecycle needs; record source/digest. A mixed installation exposing only the old universal contract is not the migrated coordination capability: block delegation, not equivalent direct research, until a compatible library is available. Do not create another coordination owner here. Recorded acceptance corrections additionally need the responsible lead's repair procedure and retained checkpoint/finding budget; ordinary research is not acceptance repair.
3. **Use the existing root.** Under a delivery lead, request a slot/assignment from that root; a research worker cannot spawn helpers. Standalone, the caller owns the bounded root and its active-assignment record. Reserve capacity, exact source/question scope, ownership, authority and a finite timeout/turn/tool bound before launch. Use read-only workers where sufficient; if a worker cannot write, it returns findings for caller-authorized retention. Keep unrelated work outside scope and avoid unnecessary private context in inherited prompts.
4. **Supply a self-contained handoff.** Include question/purpose, agreement/revision and acceptance IDs if applicable, confirmed decisions, source/version scope, existing evidence identities and gaps, permitted access/disclosure/effects, protected files, output contract, stop/block conditions, worker identity/isolation and lifecycle bounds. Ask for claim locators and actual observations, not just a recommendation. No downstream implementation or model calls are implied.
5. **Retrieve and inspect.** Follow the runtime's completion notification/retrieval mechanism. Inspect actual artifacts and cited source content, confirm version/date applicability, check unsupported or conflicting claims and compare deciding input identities before accepting the return. Perform the entry point's final return check; retain caller accountability rather than forwarding an unchecked worker summary.
6. **Handle failure honestly.** Record partial/failed/expired results and gaps. Keep unknown worker state, scope ownership and capacity reserved until confirmed stopped or isolated. Resume reconciles actual state and spent ledger use rather than blindly relaunching. Missing capability/permission blocks immediately; recorded acceptance corrections follow the responsible lead's existing checkpoint/repair allowance without resetting it. User-directed persistence does not erase active owners, uncertain operations or spent allowances; stop/isolate safely or retain necessary live state at an approved location before ending an unsafe session. If neither route is authorized, report the blocker rather than inventing released ownership. If safe and authorized, finish equivalent remaining research directly; otherwise return partial/blocked evidence and the required next action.
