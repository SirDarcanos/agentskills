# Optional background research

Read only when considering background delegation. The calling agent remains accountable for scope, source checking and return quality.

1. **Check authority and capability.** Delegation needs current request/project permission, authorized disclosure to the worker and a runtime with finite lifecycle bounds and separately inspectable source/results. Direct research is the default when equivalent and allowed. If background-only execution is required, missing capability blocks that route. Do not launch merely because the runtime exists.
2. **Resolve the shared execution contract.** Discover `work-on` through the catalog or an explicit approved package location. Read its complete entry and `references/contracts.md` as a read-only library; this does not invoke delivery. Require shared worker capacity, exclusive ownership, finite bounds, no recursive fan-out, result inspection and persistent repair lineage. Record the resolved source/digest. A missing/incompatible library makes delegation unavailable, not ordinary direct research. Read only relevant additional references when recovering or correcting work under that contract; avoid duplicating its limits here.
3. **Use the existing root.** Under a delivery lead, request a slot/assignment from that root; a research worker cannot spawn helpers. Standalone, the caller owns the bounded root and its ledger. Reserve capacity, exact source/question scope, ownership, authority and a finite timeout/turn/tool bound before launch. Use read-only workers where sufficient; if a worker cannot write, it returns findings for caller-authorized retention. Keep unrelated work outside scope and avoid unnecessary private context in inherited prompts.
4. **Supply a self-contained handoff.** Include question/purpose, agreement/revision and acceptance IDs if applicable, confirmed decisions, source/version scope, existing evidence identities and gaps, permitted access/disclosure/effects, protected files, output contract, stop/block conditions, worker identity/isolation and lifecycle bounds. Ask for claim locators and actual observations, not just a recommendation. No downstream implementation or model calls are implied.
5. **Retrieve and inspect.** Follow the runtime's completion notification/retrieval mechanism. Inspect actual artifacts and cited source content, confirm version/date applicability, check unsupported or conflicting claims and compare deciding input identities before accepting the return. Perform the entry point's final return check; retain caller accountability rather than forwarding an unchecked worker summary.
6. **Handle failure honestly.** Record partial/failed/expired results and gaps. Keep unknown worker state, scope ownership and capacity reserved until confirmed stopped or isolated. Resume reconciles actual state and spent ledger use rather than blindly relaunching. Missing capability/permission blocks immediately; corrective assignments follow the shared contract's existing checkpoint/repair allowance without resetting it. If safe and authorized, finish equivalent remaining research directly; otherwise return partial/blocked evidence and the required next action.
