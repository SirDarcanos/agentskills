# Investigate Bug

Confirm a reported defect, establish its cause and produce a workable ticket through Write Tickets. Start at [SKILL.md](SKILL.md). An investigation-only request stops at the ticket; repair is a separate authorized delivery action.

Copy this complete directory, including its license and [validation guidance](references/validation.md), into your runtime's skill discovery path. No installation is performed by invoking it. The runtime needs file inspection/search and authorized command execution for runnable diagnosis. Tracker persistence additionally needs compatible `write-tickets` and its discovered native tracker procedure; missing approval or capability returns supported findings/drafts, not a publication claim.

Companions resolve through the runtime/project catalog or an approved location, including non-sibling installations. Analyze and Research fill material gaps only; current complete evidence is reused. Work On's read-only execution contract is conditional on separately authorized delegation. A later delivery route must satisfy that lead's actual invocation and capability gates.

Confirmed, intermittent, unconfirmed, unresolved-cause, duplicate and stale-input routes preserve actual observations and artifact disposition. Diagnostic probes never authorize a product fix. See validation for offline checks and their limits.

This is original instruction prose derived from the #48 bug contract and accepted #50 design; no external diagnosis procedure or template is imported.
