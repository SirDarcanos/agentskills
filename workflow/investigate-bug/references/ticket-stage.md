# Selected ticket stage

Read only when the request selects ticket preparation/publication/reconciliation, including an explicit investigation-and-ticket compound. This reference routes the diagnosis to the ticket owner; it does not make a ticket a diagnosis prerequisite.

1. Discover compatible `write-tickets` through runtime/project guidance and inspect its complete entry and relevant references. Require bounded ready-bug or explicitly investigation-only input, selected publication with draft overrides, duplicate/partial-write reconciliation, exact relationship/label authority and verified read-back. Missing or incompatible capability blocks this selected stage; return supported diagnosis and the specific artifact blocker without installation or an invented ticket.
2. Supply current step 4 diagnosis, deciding identities/raw observations, expectation and acceptance, fix scope or unresolved diagnostic scope, protected work, probe disposition, original requested effects and existing issue evidence if available. Preserve compound authority: do not ask for a second command or duplicate approval of unchanged commitments/routine wording. New consequential scope or uncovered tracker effects still need their owner's decision.
3. Let Write Tickets own tracker discovery, duplicate search, native graph inspection, title/body/classification, approved writes and read-back. Compare matches by symptom, contract, versions/environment and cause, not title alone. Incomplete access leaves duplicate/graph state unknown; never invent absence, create around an ambiguous match, or substitute body links for required native relationships. Preserve unrelated body, labels and edges; no artificial parent, automatic readiness, closure or scheduling.
4. Inspect the actual return and deciding-input freshness, not just its status. Verify persisted contents/classification and raw read-back against authorized effects. On partial/unknown writes, preserve actual successes/failures/unknowns and require bounded reconciliation before retrying; do not replay creation blindly. A canonical duplicate names the inspected issue and actual authorized delta, including a verified no-op when appropriate.
5. Return the selected artifact outcome separately from diagnostic readiness:

   | Ticket outcome | Required return |
   | --- | --- |
   | Published/reconciled and read back | Linked canonical issue ID and concise description, actual delta and verified read-back; no full-body paste required |
   | Draft/local-only or publication declined | **Draft — not published**, actual authored draft if available and selected zero-write disposition; no fabricated ID or pressure to publish |
   | Missing authority/access/capability or partial/unknown persistence | **Partial/blocked ticket stage**, actual operations, missing permission/capability/read-back and bounded next action; supported diagnosis remains available |
   | Unconfirmed symptom or unresolved cause | **Investigation-only** draft or authorized diagnostic ticket; attempted evidence, remaining hypotheses, diagnostic acceptance and next action, never ready-fix scope |

**Done:** the selected ticket stage has an inspected actual outcome or a specific blocker, independently of diagnosis status. Recommend further work when useful; continue only responsibilities already selected and authorized. A ticket or successful publication is not delivery authority or acceptance.
