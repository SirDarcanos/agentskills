# Optional model allocations

Read only for a separately requested/authorized assessment or unresolved prior usage. Optional `ask-*` skills are never required companions or reviewer substitutes. The target project owns permissions and limits; this library owns shared allocation accounting, not a model-use policy.

1. Before proposing a call, inspect the target's authoritative model-use policy and exact named package's complete entry/references. Require applicable purpose, skill/variant/model/service/endpoint, disclosure/retention, call/retry/spend and lifecycle/fallback authority. Missing, none, conflicting or exhausted permission means zero autonomous calls. Availability/credentials are not consent. Explicit named requests retain package gates and target restrictions.
2. The root reserves shared allowance before sending; the assessment owner rechecks immediately before send. Record attempted requests, transport retries, correction calls and failed/unknown-charge attempts. Reconcile without replenishing on method switch, worker handoff, integration or resume. Use stricter policy/package limits, including at most one evidence-corrected assessment request. Unknown usage or unsafe cost reservation blocks the call. Workers request root allocation, not recursive pools.
3. No silent service/model substitution. Startup/shutdown follows approved lifecycle ownership; reused services stay untouched. Installation/downloads/credentials remain separately gated. Missing/invalid results stay unavailable; valid insufficient-data results stay gaps, not a retry-until-green instruction. Retain results only within approved disclosure/retention.
4. Continue ordinary engineering when evidence suffices; otherwise report the material gap. Optional judgments establish neither deterministic facts, executed checks, independent review nor acceptance. Preserve uncertain usage through recovery; absent optional permission alone does not block delivery.
