# Ticketing compatibility route

Retained compatibility adapter for an authorized ticket/publication or graph-reconciliation handoff, not a scheduling route from the single-change entry. Write Tickets remains independently invocable; multi-unit delivery requires the discovered `work-on-spec` coordinator. Write Tickets owns the procedure; this adapter owns only the delivery handoff. For changes, read [ticketing validation](ticketing-validation.md).

1. Use [capability checks](contracts.md#capability-checks) to discover compatible `write-tickets` through the runtime/project or approved package location, not a sibling path. Read its complete entry and relevant references; record source/revision or digest. Require cohesive agreement/bug input, evidence freshness, exact publication/graph approval, native parent/blocker/role read-back, duplicate/partial-write reconciliation and no automatic readiness/scheduling. Missing or ambiguous capability blocks ticketing, not unrelated entry inspection; no legacy fallback.
2. Supply the [handoff envelope](contracts.md#handoff-envelope): pinned approved agreement and technical readiness, acceptance IDs, current graph/protected state, exact authority and expected return. Reuse current evidence without restarting analysis. A bounded bug investigation may be consumed directly; missing cause is not ready implementation.
3. Execute in the lead's context unless separately authorized delegation is justified. Inspect returned actual ticket contents, identities/draft bindings, approval, role/readiness outcomes and both-direction persisted parent/blocker evidence against the approved delta. Failed/unknown reads remain blockers; plan-only is not publication.
4. Within the existing delivery request, choose [direct build](build.md) for one ready cohesive change. For multiple tickets return to the overall lead or discovered `work-on-spec`; missing/incompatible coordination is a blocker, not permission to run retained dispatch material. Load and check that procedure; graph verification alone proves neither predecessor accepted integration nor execution authority. Preserve partial operations for [recovery](recovery.md).

**Complete when:** the inspected specialist outcome is recorded as verified, plan-only, partial or blocked, protected work is preserved and the authorized next delivery gate or concrete blocker is identified. Standalone Write Tickets stops at its return, not this continuation.
