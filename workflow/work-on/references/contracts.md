Compatibility library for callers still using these anchors. Reading it does not invoke delivery. The target project's meaningful agreement owns common operating policy; ordinary Work On entry does not load this library. Keep these live targets until their callers migrate. Follow the linked procedural owner only for the capability actually used.

## Capability checks

Use target/runtime discovery and common reading rules. Inspect the resolved compatible entry (or documented direct library entry) and relevant branch references, source/revision or digest and required authority. Missing/ambiguous capability blocks its dependent route, not unrelated work; no installation or legacy fallback. Local method/preflight responsibilities are in [build](build.md). Native GitHub graph work discovers the actual `setup-project` package root and reads its complete `references/native-tracker.md` library entry directly, without the setup entry or label audit; missing/incompatible libraries block that route without installation. Diagnosis can return actionable conversation evidence without mandatory ticket publication.

### Complete reads and reference resolution

Recover omitted required output using retained output or focused/ranged reads before dependent action. Resolve references from the complete inspected entry relative to the actual package, never guessed filenames/sibling trees. After ENOENT inspect the documented pointer/layout; distinguish a stale guess, unavailable inspection and genuinely missing material. Resume compatibility/authority checks after recovery. This grants no installation, stub creation, setup invocation or weakened graph requirements.

## Handoff envelope

Ordinary conversation supplies agreement/acceptance, deciding context and raw evidence, exact authority, owned/protected scope and actual state, expected outcomes/checks and blocking conditions. Receivers inspect sources, not just summaries. Delegated assignments additionally use [coordination](coordination.md#assignment-and-lifecycle); no mandatory envelope file is required.

## Lead evidence record

Same-session evidence can remain in conversation under target guidance. Retain actual check commands/results and checked state/supporting inputs, original review reports, limitations, documentation disposition and distinct delivery gates. Full dirty snapshots belong to discovered `review-delivery`, not HEAD-only summaries. Changed inputs invalidate dependent claims; content-identical commits need explicit equivalence and state-sensitive reruns.

Persistence is user-selected. When PR/issue evidence publication is selected and authorized, keep technical detail and original reports in a dedicated comment or collapsed **Validation details**, with material caveats visible in the short summary; inspect read-back. Otherwise return evidence conversationally without treating absent routine storage as a delivery blocker. Active owners, uncertain effects and spent repair/model allowances still require safe accounting through [coordination](coordination.md), [completion](completion.md) and [recovery](recovery.md). Keep reusable checks committed; do not create routine committed execution reports or remove historical evidence.
