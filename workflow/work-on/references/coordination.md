# Conditional coordination library

Read before authorized delegation, or when active/uncertain workers require reconciliation. This library owns lifecycle, root allocation and ownership mechanics, not common project policy or delivery invocation. Inspect applicable target agreement and originating authority first. Ordinary direct work needs no worker ledger. Recorded acceptance repairs additionally use [completion](completion.md#2-perform-bounded-repairs-and-inspect-results); optional assessments use [model allocations](optional-models.md).

## Required-review authority

An explicit user delivery request through `work-on` or `work-on-spec` authorizes the required bounded read-only Standards and Spec reviewer contexts through the configured agent runtime, without another permission prompt solely for delegation. This authority travels with the packages: no repository-local standing permission is required. A bounded ticket assignment inherits this review scope from its authorized delivery root; the ticket worker requests review from that root rather than launching reviewers itself. Loading a skill or reading this library grants no execution authority, and a standalone review caller must establish its own review permission.

Explicit user/project/runtime restrictions take precedence. Record the originating request, scope and existing data/usage boundaries. New sensitive disclosure, additional spending, installation or service/account changes require separate approval. This grant excludes optional implementation/exploration workers and optional model assessments, merge, deployment and release. Missing capability or a restriction leaves implemented-but-unaccepted work; do not invent a missing-permission problem solely because no local standing policy exists.

## Lead-chosen concurrency

1. The root lead alone reserves and launches assignments under one shared execution record. A bounded standalone consumer is its own root; ticket workers request additional work/review rather than creating another pool.
2. The root lead chooses and adjusts concurrency using eligible work, ownership/interface coupling, review demand and actual runtime/resource capacity. Record the choice/rationale. There is no universal worker ceiling or fixed batch size. Explicit user/project restrictions, permission, disclosure and spending limits still apply. An update does not override an existing consumer-project restriction; propose exact reconciliation instead.
3. Account for every submitted unfinished assignment, including idle/uncertain workers. Unknown lifecycle retains its ownership and capacity; it blocks conflicting replacement, not unrelated safe progress. Declare finite timeout/turn bounds and inspectable result/lifecycle controls before launch. Workers cannot recursively delegate or automatically call optional models.
4. Reassess after completion, integration or resource changes. Use rolling scheduling of useful eligible work, preserving scoped freezes; unrelated work need not wait for a cohort. Whole-spec eligibility/frontier/integration belongs to discovered `work-on-spec`, never this library.

## Assignment and lifecycle

1. Supply the bounded agreement/acceptance, actual source/state and raw evidence, exclusions/protected work, exact effects/approval source, expected result/checks, owner, isolation, finite bounds and remaining checkpoint/allowance state. Conversation or existing root records suffice; do not manufacture a new handoff artifact.
2. Writes require exclusive scope and stable interfaces. Serialize shared interfaces or assign one owner. The lead integrates one inspected result at a time under target branch policy. Freeze scoped writes/integration during verification/review or supply an authorized immutable snapshot.
3. Review uses two read-only contexts, Standards and Spec, independent of authors and each other's conclusions. Sequence with one slot when needed. Lead self-review cannot substitute. Discovered `review-delivery` owns neutral packet boundaries, snapshot mechanics and original axis reports.
4. Inspect actual returned artifacts, scope/authority compliance and raw checks, not a worker's success summary. Preserve partial/failed artifacts. On failure/expiry confirm the prior owner stopped or is safely isolated before replacement. A crashed session does not free ownership.
5. Retain root assignments/status, reserved scopes/interfaces/capacity, unknown operations and checkpoint/finding/model usage through transfer/resume. Reconcile actual state before retry/replacement. User-selected persistence cannot erase live safety obligations: stop/isolate safely or retain necessary state at an approved location; otherwise report the blocker. Ordinary inactive findings need no durable run report.

**Complete:** bounded assignments have inspected terminal results, or explicit retained ownership/uncertainty and next actions. Missing runtime capability permits equivalent direct work, never invented independent review or assumed worker termination.
