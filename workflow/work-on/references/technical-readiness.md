# Technical readiness compatibility route

Read when Work On selects missing or materially changed codebase/design/risk evidence. The procedure now belongs solely to the independently installable `analyze` companion; this file retains the old route, not a second analysis procedure. For route changes/checks, read [technical-readiness validation](technical-readiness-validation.md).

1. Apply the target's discovery rules through the runtime/project catalog or an explicit approved location. Read the complete `analyze` entry and relevant references; record source/revision or digest. Require bounded standalone/handoff analysis, inspected code/callers/reuse/coverage, deciding-input freshness, risk/check mapping, selective research/domain use, method recommendations and an honest stop without implementation. Missing, ambiguous or incompatible Analyze blocks this responsibility; return the useful handoff and exact discovery/approval next action without installation or legacy substitution.
2. Supply current context in conversation or the existing evidence home: approved agreement/acceptance and exclusions, current/prior technical or bug evidence, deciding sources/state, protected work, exact authority and expected brief/method/check return. Reuse complete current analysis directly; do not invoke Analyze solely because another phase started. Execute needed analysis in the lead's context; delegation remains separately authorized and bounded.
3. Inspect its actual return against agreement, source freshness and authority. The lead decides the method/sequence from the recommendation, retaining blockers, planned versus executed checks and domain/documentation disposition. A supported recommendation with an unavailable method is not executable delivery. Apply [build readiness](build.md#1-establish-readiness-and-ownership) separately, including dependencies, execution authority and Git preflight; analysis alone grants no acceptance.
4. Within the active single-change delivery request, choose direct build when ready. If analysis reveals multiple work units, return the boundary to the overall lead or discovered `work-on-spec`; do not schedule them here. For the selected single-change gate, load the complete shipped destination from entry and check its capabilities. If unavailable, return the inspected brief and affected-route blocker. A standalone Analyze invocation stops at its own return rather than taking this continuation.

**Complete:** an inspected reused/new Analyze return and lead next-gate decision, or a specific affected blocker. Work On now owns only single-change delivery; Analyze remains the sole analysis owner, and method packages own implementation loops.
