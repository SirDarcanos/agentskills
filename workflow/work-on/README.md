# Work On

Deliver or resume **one bounded change**. The calling agent is the technical lead: it consumes current agreement/investigation/analysis, chooses the engineering method, builds directly or through authorized workers, verifies, obtains independent review, repairs within bounds and returns checked, reviewed delivery status with PR-ready work or explicit limitations. Ordinary delivery stops before PR preparation/publication; offer that stage and run it only when selected.

Use `/work-on <change or actionable ticket>`, an ordinary explicit delivery request, or an authorized bounded assignment from an overall lead or investigation-and-fix caller. Investigation-only requests stop at diagnosis; discovery of this skill is not permission to fix.

## Changed boundary

Whole-spec delivery, multi-ticket scheduling and overall recovery belong to independently installed `work-on-spec`. Until a compatible coordinator is discoverable, that route is unavailable; Work On preserves partial artifacts and reports the boundary instead of running its old dispatch procedure. Only compatibility pointers remain here.

This is an incompatible invocation boundary, although Work On has not yet been included in a published release. A specification can still provide acceptance for one bounded assignment. Existing current bug/analysis evidence is consumed directly; only missing or invalidated facts trigger specialist work. The lead chooses methods without asking the maintainer to pick routine test seams or techniques. Requested reusable-skill corrections target the tracked package sources; a local operating-policy workaround does not replace the portable fix, and installed copies are a separately approved target.

## Install and dependencies

After approving installation, use the repository CLI convention:

```sh
npx skills add SirDarcanos/agentskills --skill work-on
npx skills add SirDarcanos/agentskills --skill implementation-preflight
npx skills add SirDarcanos/agentskills --skill review-delivery
# Only if you also want the separate PR stage:
npx skills add SirDarcanos/agentskills --skill pr
# Select the method needed for your change, for example:
npx skills add SirDarcanos/agentskills --skill build-and-check
```

These examples are not automatic workflow actions and have not been executed by this change. Review collisions and destination scope before installation. Alternatively copy/link the complete package with its [MIT notice](LICENSE) and references into the runtime's discovery path. A repository merge does not update separate installed copies; global replacement requires separate approval.

Start at [SKILL.md](SKILL.md). A meaningful target-project agreement is required; compatible existing guidance needs no ceremonial Setup run or prescribed filenames. Missing common guidance gets a specific reconciliation recommendation, not invented policy. [Coordination](references/coordination.md) is loaded only for delegation/active workers, [completion](references/completion.md) owns recorded repair counting and [optional models](references/optional-models.md) is conditional on separately authorized assessment work. [Contracts](references/contracts.md) preserves library targets for unmigrated callers, without being an ordinary-entry dependency. Resolve companions through the runtime/project catalog or an explicit approved source, inspect semantic capabilities and record source identity. Names and sibling paths are not a compatibility contract.

| Responsibility | Companion / condition |
| --- | --- |
| Git preparation | Required compatible `implementation-preflight`; current same-scope supplied preflight may be reused. Non-Git work uses a manifest. |
| Missing bug facts | `investigate-bug`; consumes only diagnostic gaps and returns current actionable evidence, never fixes inside investigation. |
| Missing technical readiness | `analyze`; current complete analysis/bug evidence bypasses a fresh run. |
| Missing product commitments | `shape-work` for discovery, `write-spec` for expression/revision; current clear requests need no hierarchy. |
| Selected method | `tdd`, `prototype`, `characterize`, `acceptance-first` or `build-and-check`; each owns its own loop. Sequence learning/protection before implementation where useful. |
| Independent acceptance review | Required `review-delivery` and separate read-only Standards/Spec contexts; unavailable review leaves implemented-but-unaccepted work. |
| Selected PR decision report/publication | `pr` only when the user selects that stage; reuse current raw delivery evidence, never infer merge permission. |
| Changed meanings or qualifying ADRs | `domain-modeling`; reading existing definitions needs no invocation. |
| Ticket publication/reconciliation | `write-tickets`; no automatic scheduling or ticket closure. |
| GitHub native graph | Discovered `setup-project` tracker reference as a library, without invoking setup or its setup-only companions. |

The runtime needs authorized file inspection/edits and target-specific checks, Git/tracker access where relevant, and bounded independent reviewer capability for acceptance. Direct building is the default. An explicit delivery request includes required read-only Standards/Spec reviews under [required-review authority](references/coordination.md#required-review-authority), even without a repository-local permission policy; explicit restrictions still prevail. Optional implementation/exploration delegation needs separate permission. All delegated work retains exclusive ownership where applicable, finite bounds and one root coordination record; ordinary direct work needs no new ledger. The root chooses and adjusts concurrency under [lead-chosen concurrency](references/coordination.md#lead-chosen-concurrency), without a fixed worker count or batch size; explicit project/runtime constraints still apply. A ticket lead cannot launch a second pool. Shared repair history survives method switches and resume.

Optional named `ask-*` assessments need exact approved project policy and shared allowance; availability or credentials are not permission. Missing optional models do not block ordinary engineering where evidence suffices. No model is required, and no optional assessment replaces verification or review. This repository has no approved model-use policy and performs no calls in ordinary validation.

## Results and validation

Work On reports implemented, verified, unverified, deferred and blocked scope separately, with artifact/evidence pointers, documentation/changelog disposition, remaining findings and actual PR/issue state. Build, accept and report gates are distinct from maintainer acceptance, merge, installation, deployment and release. Material unavailable checks and independent review gaps remain acceptance blockers.

Read [single-change validation](references/single-change-validation.md) for fixtures and evidence limits, and [entry validation](references/validation.md) for package checks. Same-session results and original reviews can remain in conversation. Persistence is user-selected, not a mandatory durable report/handoff; active owners, uncertain operations and spent allowances still need safe accounting. Feedback reopens only affected implementation/checks/review. A later explicit PR request reuses current evidence and keeps merge separately approved.
