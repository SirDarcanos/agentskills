# Shape Work

Clarify an idea in project terms: goals, users, scope, priorities, constraints, trade-offs and success. Start at [SKILL.md](SKILL.md) for standalone discovery or a bounded caller handoff. It asks focused follow-ups across relevant workflows, exceptions and trade-offs, retains required/deferred/excluded/accepted-limitation dispositions, and visibly tracks what remains. Each round asks the next questions, names a blocker, or presents a brief for confirmation. It explicitly says “Shaping complete” only after the agreement is usable and confirmed; document updates alone do not end discovery.

Current decisions and supported research/analysis are reused. Readily available reliable facts are inspected directly; technical gaps go to compatible Analyze or Research, not questions asking you to design internal abstractions or test seams. Analysis that could change behavior, feasibility, compatibility, scope or consequential trade-offs happens before brief confirmation, directly in the caller's context without a separate `/analyze` command. Implementation-only analysis may remain a later phase when it cannot change the agreement. Missing goals, expectations and other owner-held context are asked directly rather than inferred from search. For work spanning people/items, readiness covers each in-scope item, not just shared guidance; deferring required context needs owner agreement. Actual meaning or decision-record changes use Domain Modeling with its own approval gates.
