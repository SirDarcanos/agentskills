# Shape Work validation

Read when changing or exercising [Shape Work](../SKILL.md). Use safe synthetic targets; no real tracker mutation, installation, model call or delegation is implied.

## Package checks

1. Read/render all changed Markdown and verify entry name/description, ordinary matching and bounded handoff routing, ordered steps and checkable complete/partial/blocked returns.
2. Follow every relative link/anchor from the entry and its shipped references. Copy only this package to a temporary non-sibling location and repeat; internal links stay inside it. Conditional companions use catalogs or approved locations, never `../companion` paths.
3. Inspect the actual diff for private data, local paths, generated files, duplicate discovery bodies and notice loss. Preserve historical repository execution records.
4. Check Work On's adapter and entry/contracts together: existing approved actionable agreement bypasses new discovery; unresolved intent requires compatible Shape Work; missing helper blocks only discovery. Spec writing/publication uses discovered Write Spec; Shape Work stops at its brief.
5. Run relevant existing offline package checks; this instruction-only package has no runtime script or shared test suite. Report commands, environment, actual results and unrun checks separately from the scenarios below.

## Behavioral cases to execute

Use direct in-session walkthroughs or separately authorized agents, labeling which. Supply non-technical user turns and inspect facts through specialist procedures; authored expected outputs alone are not execution evidence.

| Case | Inspectable result |
| --- | --- |
| Non-technical feature conversation | Manageable rounds on goal/users/priority/constraints/success; explain consequential options in user/scope/cost/risk terms, not seams or internal abstractions; stop only when every relevant concern is decided or explicitly dispositioned |
| Thoroughness versus pacing | Several rounds leave a relevant recovery question unresolved; continue with that question, reusing settled answers and investigating discoverable facts. An explicit session limit returns remaining concerns, not a complete agreement |
| Recorded details but shared workflow questions remain | Acknowledge settled details, say Still shaping, and ask the next specific questions in the same response. Document/link success is not a closing signal; the user never needs to prompt for remaining questions |
| Brief broad answer leaves priorities or exception behavior ambiguous | Test with a concrete workflow/example and relevant exception/trade-off; ask focused follow-ups until consequential ambiguity is resolved, without reopening settled details or inventing requirements |
| Confirmation and corrections | Present Ready for confirmation, explicitly not complete; wait for the owner. A correction reopens affected questions only; confirmation plus current complete evidence permits an explicit Shaping complete return, with exclusions and recommended next phase but no automatic progression |
| Shared guidance settled but current people/items have incomplete context | Check each in-scope item, expose missing/uncertain inputs and ask focused owner questions without waiting for a readiness challenge. Report shared versus individual readiness separately; no overall complete claim or unilateral deferral |
| Shared-only request versus broad preparation request with unclear boundary | Reuse explicit scope; otherwise ask early whether readiness includes current people/items. Do not silently narrow broad preparation to shared rules. Defer required inputs only with owner agreement and revisit condition |
| Owner-held priorities/expectations versus searchable historical activity | Ask directly for agreed goals and tacit context; inspect reliable records for sourced facts. No speculative inference, exhaustive search to avoid asking, or demand that the owner reconstruct readily available history |
| Four dispositions | Required, deferred with revisit, excluded with reason, limitation explicitly accepted; proposed limitation remains unaccepted before its confirming turn |
| Current settled decision | Inspect agreement and cited deciding inputs; reuse unchanged decisions/findings, zero new interview or automatic specialist call, no duplicate artifact |
| Changed fact | Refresh dependent question only, preserve unaffected intent and old evidence; unclear impact expands relevant stale set honestly |
| Fact/domain gap | Bounded Analyze/Research handoff with inspected support; domain work only for changed meanings/qualifying decisions, plan-only without write permission |
| Missing/incompatible/ambiguous companion | Specific affected-route blocker, preserved draft and smallest next evidence action, no install or legacy fallback |
| Bound/intent/authority blocker | Partial draft or blocked consequential agreement, owner and next action; no invented consent or automatic publication/build |
| Isolated/standalone and caller route | Package links survive non-sibling copying; companion source resolved explicitly; standalone stops, authorized caller inspects then chooses next gate |

## Evidence limits

Static assertions and authored scenarios do not establish agent compliance. Direct synthetic conversations show the author's observed application, not an independent user/agent trial, installed discovery or composed delivery acceptance. Retain actual repository evidence separately from this reusable guidance; do not copy private transcripts into the public package. No universal question quota, test count or method is imposed.
