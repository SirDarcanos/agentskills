# Write Spec validation

Read when changing or exercising [Write Spec](../SKILL.md), including [publication](publication.md) when testing persistence. Use synthetic local targets; no public mutation, installation, model call or delegation is implied.

## Package checks

1. Read/render changed Markdown; inspect frontmatter routing for ordinary requests and bounded handoffs, ordered actions and checkable complete/partial/blocked returns.
2. Resolve every shipped relative link/anchor, then copy only this package to a temporary non-sibling location and repeat. Companions are discovered, not relative sibling dependencies.
3. When validating a caller integration, discover its actual instructions: supplied current agreement needs no new shaping/analysis, and missing helpers block only dependent work. A caller/source checkout is not a prerequisite for this package's own validation.
4. Inspect diff for private data, nonportable paths, generated files, duplicated procedure bodies and lost notices. Preserve historical evidence.
5. Execute agreed-input writing and publication via safe tracker fixtures; record actual artifact and mutation/read-back observations separately from authored expected cases. This instruction-only package has no runtime spec generator or shared test suite.

## Behavioral cases

| Case | Inspectable outcome |
| --- | --- |
| Configured agreed-plan command | Publish/read back the actual specification and mapped role; return link plus concise summary, with zero duplicate full-text approval or unsolicited tickets |
| Explicit draft/local/review-only request | No tracker writes; return the selected draft/review, not a publication claim |
| Missing access/destination/authority | Specific publication blocker and preserved useful writing, no forced plan interview or implementation |
| Ordinary agreed input / existing discovery brief | Faithful spec with behavior, rationale, exclusions, limitations and acceptance IDs; no forced Shape Work session |
| Current evidence / changed deciding input | Reuse complete current findings without calls; invalidate only dependent claims when inputs change, retain unaffected intent and old evidence |
| New unapproved commitment | Labeled proposal/draft; owner approval required before reliance; separately authorized draft publication stays draft, not implementation-ready; a defined human decision may justify human readiness |
| Existing authoritative spec / duplicate match | Revise approved home within authority, preserve IDs/history and unrelated content; no second spec issue; ambiguity or failed search stops creation |
| Local brief / missing write permission | Proportionate conversation return or exact proposed delta; no forced issue or persistence |
| Mapped roles / independent readiness | Equivalent target mappings honored; spec/work-ticket roles exclusive; publish/read back justified agent-ready or human-ready next actions alongside the spec role, regardless of native blockers, without duplicate routine-classification approval. Open design is not implementation readiness; identify a concrete human next action or the missing evidence |
| Readiness versus scheduling | Blocked/unblocked agent and human work retains equivalent readiness; preserve native edges; ready parent coordinates eligible children, never duplicate implementation or blocker bypass |
| Role conflict / stale readiness | Correction requires exact authority; contradictions are blockers, not silent label cleanup |
| Timeout / failed or mismatched read-back | Retain partial/unknown effects, inspect before retry; no duplicate creation or false publication success |
| Missing/incompatible/ambiguous companion | Block dependent route, retain useful writing and smallest next action; no installation/fallback |
| Standalone / caller stop | Spec return stops before tickets/build; authorized caller inspects then selects its next responsibility |

## Evidence limits

Authored scenarios and keyword/static checks do not prove instruction-following. Direct in-session applications show the author's observed use; fixture persistence proves only fixture operations, not GitHub API behavior. Independent agent and composed delivery trials require separate authority; record unrun checks explicitly. Retain actual repository evidence outside the reusable package and keep private transcripts out of public artifacts.
