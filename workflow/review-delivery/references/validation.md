Read when changing or validating this package. These are reusable checks and trial scenarios, not retained execution reports. Keep results and original axis reports in conversation or a user-selected approved evidence home. When selected publication is authorized, use a collapsed **Validation details** section or dedicated PR/issue comment, outside the installed skill. Do not load a universal delivery contract solely for common policy or retention. Include commands/results, checked state and supporting-input identities, limitations and a retrievable pointer; keep material failures, unrun checks and unresolved blockers visible in the short summary. Use temporary local intermediates, not new committed execution reports. Reusable checks remain committed and runnable. Unrequested persistence is not a storage gap. ## Local checks

Python 3.9+ and Git are required for the optional helper tests. From this package directory:

```bash
python3 -B scripts/test_snapshot.py
python3 -B scripts/test_contract.py
```

In a Git source checkout, also run `git diff --check`. Read changed Markdown/frontmatter, inspect rendered headings/tables/code blocks, and resolve relative links/anchors from their containing files. Verify that the description routes delivery reviews and bounded handoffs. Copy only this package to a temporary directory and run its tests there; no sibling package or workstation path should be needed. Inspect the full diff, including untracked files, for private data, generated artifacts, nonportable paths and unintended legacy-skill changes.

### Executable fixture scope

The offline tests use temporary synthetic Git repositories. They cover committed/staged/unstaged changes, included untracked files, deletion/rename endpoints, file modes, leaf symlinks, supporting inputs and protected unrelated work. They exercise index-only/content-identical-commit drift, invalid capture inputs and unchanged protected bytes/index/history. A repair fixture demonstrates input drift despite unchanged passing-log bytes, and the limit that repinning cannot certify a log was rerun. A generator check compares literal symlink-target and observed non-following mode evidence, and verifies maintenance/test expectations stay outside the review packet.

The fixture's dirty formatter changes case; an untracked module duplicates normalization ownership. Tests demonstrate defect observability and helper drift detection, not independent reviewer finding detection. A new file outside the explicit path list intentionally leaves the helper capture unchanged: separate discovery must identify it before repinning.

## Behavioral trial (requires separate permission)

1. Use `python3 -B scripts/trial_fixture.py` to create a retained synthetic target and initial evidence. The generator launches no agents; the caller owns retention/cleanup. Read the generated brief/standards, pin all relevant source/support inputs, and keep unrelated sentinels protected.
2. Follow [handoff](handoff.md): discover the conditional coordination library outside a sibling layout, record its source/root execution record, and confirm inspection-only delegation authority, independent contexts, finite bounds and available slots. Freeze included files/support and provide actual diffs/files, generated `evidence/link-evidence.json` for non-following literal symlink metadata, exact check commands/environment and supporting-artifact fingerprints. Filter supplied patches as well as file/search roots to exclude test expectations and verdict-bearing history. Keep each axis's conclusions out of the other reviewer's context.
3. Execute Standards and Spec separately using this skill and its report contract. Check whether they detect the dirty case regression and untracked duplicate ownership with locations, rationale and materiality. Retain actual reports, not authored expected findings.
4. After initial reports, change an included untracked file and add a relevant caller. Repeat discovery/fingerprints and require affected evidence to be marked stale; repin before renewed review. An unchanged HEAD or tracked patch cannot identify untracked state.
5. Include a prior-report exposure case: place retrospective verdict snippets outside the permitted source/evidence set. Directly inspect packet/search boundaries against the [packet checklist](report.md#independent-assignments). If separately authorized execution exposes those conclusions, retain the result as ineligible, stop/inspect lifecycle before replacement and renew affected axes with neutral inputs. A paper case or allowlist alone proves neither independent behavior nor a filesystem sandbox.
6. Exercise an explicitly prohibited or unavailable-runtime handoff without launching an unauthorized worker. Missing local standing policy alone is not missing permission for an authorized Work On/Work On Spec delivery handoff. Require an independent-review acceptance blocker; lead self-review cannot substitute. Keep simulated handoffs distinct from actual runtime failures.

## Handoff failure and reuse scenarios

These are authored scenarios, not executed reviewer evidence. Record actual actions separately:

| Case | Required observed outcome |
| --- | --- |
| Standalone ordinary request / bounded local or integrated handoff | Same input checks and report owner; no forced spec hierarchy or automatic delivery; integrated agreement/snapshot is not certified by child passes |
| Delivery handoff in a project with no standing-permission policy | Inspect originating request and execution library's required-review authority; bounded independent reviews proceed without another delegation prompt. This must work with copied packages outside this source repository. |
| Explicit restriction / library read without delivery authority | Honor restriction or establish standalone permission; no unauthorized launch and no inference of authority from reading a library. |
| Missing approved agreement | Spec gap/blocker, any Standards-only result partial; no invention of acceptance |
| Current complete analysis and checks | Inspect primary sources and identities, consume evidence without automatic re-analysis/model consultation |
| Untracked delivered module / newly relevant caller | Included module inspected; rediscovery invalidates coverage for new caller even when listed-path helper check passes |
| Lead self-review / classifier verdict | Clearly labeled non-independent inspection/advice; acceptance-review blocker; zero unauthorized workers/model calls |
| Missing/incompatible execution library or no slot | Block delegated route or queue at root; no sibling fallback, nested launch, installation or capacity reset |
| Significant repair with stale passing evidence | Old reports/logs tied to old inputs stay stale; caller refreshes affected raw checks and independent review before claiming resolution |
| Finding transferred from ticket to integration / resumed work | Stable lineage, dispositions and spent limits retained; original reports unchanged and outside neutral packet |

Inspect complete shipped instructions and embedded prompts from a copied package without this collection's checkout, Git history or tracker. Common target guidance and actual task sources remain legitimate inputs. Walk compatible/missing/conflicting agreement cases, old-universal-only coordination and conversation-only evidence with retained live safety state; distinguish static guards from observed agent behavior.

Report executed/static/not-run/failed/stale results and limits. Non-Git, manual submodule capture, timeout/recovery and renewed-review branches need their own evidence; passing the local checks is not certification of those behaviors. Retain run-specific reports and revision history outside this package.
