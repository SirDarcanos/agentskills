**Status:** Accepted. This approves D1–D4 in the [session-oriented design](../design/session-oriented-workflow.md#4-approved-decision-record-and-operating-policy-reconciliation). It authorizes these records, not merge, dependent implementation, installed migration or model calls. ## Context and decision

The composable workflow exported independent specialists but made Work On's execution contract a shared source for common operating policy and recording obligations. This adds reading and bookkeeping to sessions whose requested outcome needs neither delivery coordination nor durable transfer. [#132](https://github.com/SirDarcanos/agentskills/issues/132) establishes the session-oriented product direction; [#133](https://github.com/SirDarcanos/agentskills/issues/133) defines its technical ownership and safe transition.

The target project owns one meaningful common agreement, established or reconciled through Setup or equivalent existing guidance. Project-oriented skills consume that agreement and their distinctive methods, with conditional operational references. Compatibility is semantic, not a filename, template hash, empty-record requirement or mandatory installed common-contract package. Bootstrap, advisor and non-project standalone exceptions are explicit in the accepted design.

Users select stages; the technical lead owns routine engineering within scope. Shaping can end with an agreed plan. Diagnosis can end with ticket-ready conversation evidence. Configured specification/ticket invocation selects scoped publication without a second full-text approval of unchanged commitments. Delivery performs applicable verification and independent review, then stops before unrequested PR preparation/publication. Explicit compound requests can select several stages. Ordinary session persistence is user-directed; active ownership, uncertain operations and spent allowances remain safety obligations, not optional history.

The accepted design owns the detailed caller map and staged cutover. Keep every live library target until its callers and replacement owner are reconciled. Conditional coordination, method loops, review snapshots, tracker algorithms and local/integrated verification remain with their named procedural owners. No design acceptance claims that current packages or installed copies already implement the new boundaries.

## Alternatives and consequences

- **Keep the mandatory Work On common library:** maintains one installed policy source but requires unrelated reading and couples standalone work to delivery machinery. Move policy to the project while retaining conditional mechanics with their owners.
- **Copy policy into each skill or a new common-contract package:** avoids target prerequisites or simplifies lookup, but recreates drift or another mandatory installed dependency. Preserve one project authority and short semantic entry checks instead.
- **Automatic artifact/PR/handoff transitions:** can persist more context but selects effects the user has not requested. Offer the next stage; execute it only when selected and authorized.
- **Immediate removal of legacy targets:** shortens source text but breaks unmigrated consumers. Ship coherent owner/caller changes and retire adapters only after live-caller proof.

Existing projects may need an explicit reconciliation rather than silently acquiring new permissions with a skill update. Standalone project use now requires meaningful project guidance; non-project advisory/writing/research/assessment use does not manufacture setup effects. The reading sketches establish design opportunities, not measured runtime improvement; actual closures and behavior need downstream validation.

## Preserved guarantees and integration boundary

Retain protected files/index/history/links, truthful checks and material-evidence blockers, applicable independent Standards/Spec contexts, dirty-state snapshot integrity, native dependency/accepted-integration checks, confirmed authorized domain maintenance and explicit ADR approval/history. Retain the two-cycle automatic repair ceiling and checkpoint lineage across transfers. #130 already replaced the historical two-worker ceiling with lead-chosen concurrency subject to actual restrictions; this record introduces no new worker limit or broader delegation permission. Optional assessment permissions, budgets, disclosure, service ownership, installation, destructive operations, credentials, merge, deployment and release remain separately bounded.

Domain Modeling applied this approved record delta directly. No domain meaning changed, so CONTEXT is unchanged. Repository operating guidance now distinguishes branch/commit/push authority from selected PR publication and links this decision conditionally. Shipped skill migration, tracker mutation and installation remain outside #133. Keep #133 open until its accepted records are verified and merged under repository completion policy; dependents require accepted integration and their own authorization.
