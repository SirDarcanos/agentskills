# Reading paths and static design examples

Companion to the [proposed ownership design](session-oriented-workflow.md). **Design-only reading surfaces, not replacement skills.** These deliberately bounded sketches make the proposed responsibilities countable without implementing #134–#141. They omit package metadata, detailed failure branches and maintenance validation. Consequently their counts illustrate extraction opportunities, not final package sizes, runtime tokens, timing, adherence or achieved WF-11 acceptance. Count the real migrated packages again in #143.

## Measurement boundary

Baseline is Git revision `45e5a24`. Inspection at `dd02798` found only #142's rename changes since that baseline; the five paths below are unaffected by that rename. Count UTF-8 text with Python `str.split()` (whitespace-separated words), including headings, tables, code and frontmatter. Count each entire named file once **per context**, not once per repository. Do not count repeated reads of an already available unchanged source within one context. No token conversion or timing estimate is made.

The manifest in the executable Python block below is authoritative for this measurement. Baseline uses full required entry/reference loads for the stated branches, not every linked reference. Proposed columns use the marked design sketches below, plus full unchanged files explicitly retained by the manifest. Project instructions (`AGENTS.md`, `docs/agents/project.md`, `docs/agents/workflow.md`) are reported separately and held identical in both columns, even though later agreement compaction could reduce them. Target code, specs, issue bodies, raw check outputs, file-discovery tool output and automatic harness prompts are excluded from both totals: their sizes depend on the target, and these numbers measure **instruction text**, not a complete session's context cost. Copied reviewer contexts each count project instructions and their review packet instructions again. Only the root that launches reviewers loads coordination; axis workers do not delegate or load Work On merely to review. The root reuses its reads.

Scenarios and explicit exclusions:

1. **Setup:** new local-only project; no GitHub/tracker, no domain change, no installed assessment candidates; choose an evidence-backed release convention. Baseline still mandates model-use discovery reference; proposed setup only loads that detail if an actual allowance is discussed. No reconciliation branch or settings companion. Common fixture docs are an accounting control, not a claim that a new target already has guidance: setup can bootstrap.
2. **Planning:** shape a project feature; one material feasibility question uses inline Analyze, which inspects the Build and Check candidate to support its method recommendation. No domain/source-service gap, writes, delegation, spec or ticket stage. Shape retains its substantive product questions; shorter sketch is not a fixed question quota.
3. **Investigation:** established local reproduction/cause; no technical/source gap or new record; no publication approval. Baseline must still prepare a ticket draft through Write Tickets and inspect its tracker capability/library. Proposed returns ticket-ready findings without tracker access. No approved remote writes are counted or executed. Project tracker/label guidance is an additional conditional input; included below for this baseline branch only.
4. **Bounded delivery:** ready direct Git documentation change, Build and Check selected, no graph/recovery/domain/model work; two independent reviewer contexts. Baseline proceeds to project-policy-authorized PR publication; proposed stops at delivery outcome. This endpoint difference is required by WF-08, not proof the same published artifact costs less. An explicit later PR request loads PR/impact/publication and current evidence then. No installed package validation files are required merely for editing target documentation.
5. **Whole-spec:** ready existing native graph with one independently assigned ticket using the bounded-delivery method above, no recovery/repairs/model calls. Root dispatches/integrates under project policy and performs aggregate review with two new contexts. The ticket context has its own two reviewers. This small whole-spec example exposes context duplication without implying single-ticket direct execution can replace the required ticket runtime. Required predecessor acceptance/merge is supplied; otherwise stop at the stage blocker. Project tracker/labels are counted in root and ticket contexts. Root and ticket each count the baseline PR endpoint; proposed performs neither automatically. Root library reads are de-duplicated in its own context.

README/license/maintenance tests and all recovery/delegation optional branches not selected above are excluded, except actual Work On Spec dispatch/Review coordination requirements. No shared-contract file is removed from a baseline consumer that still requires it. Work On's thin readiness/product adapters are not loaded for already complete deciding evidence. Snapshot `scope.md` is reused by verification and review in the same context, not double-counted.

## Proposed countable surfaces

These sketches refer to responsibilities defined in the main design. An implemented package must still ship its distinctive semantics and relevant unavailable-route handling. Conditional scopes in the main inventory are not waived by their absence in this representative scenario.

<!-- surface:agreement -->
### Agreement consumed by each proposed context

Read the project's applicable guidance once and identify requested scope, decision owner and permitted effects. Use meaningful existing document arrangements. Routine engineering decisions belong to the technical lead; unresolved intent, consequential scope/cost/risk and missing permissions go to the owner with a recommendation. Missing or materially conflicting agreement blocks the affected project workflow; recommend explicit setup/reconciliation without starting it or fabricating policy.

The user chooses stages. Complete the selected responsibility and offer the next action without invoking it; explicit compound requests may authorize several stages. Configured spec/ticket commands select artifact publication within agreed scope; delivery alone stops before PR publication. Preserve unrelated files, index state, modes, links and history. Unknown permission is ungranted. Destruction, sensitive disclosure, spending, installation, credentials, merge, deployment and release retain specific approval gates. Optional models require their distinct invocation or exact approved policy; availability is not consent.

Reuse current deciding evidence, inspect primary support and refresh only affected claims when inputs change. Report actual checks and material missing evidence honestly. Local checks do not replace applicable independent Standards/Spec review. Maintain confirmed authorized domain meanings and changed documentation; qualifying ADRs require explicit agreement/permission and preserved history. Follow actual release conventions without publishing releases.

Same-session scope, evidence and outcomes may remain in conversation. Persist artifacts only to the selected destination; do not manufacture handoffs or future-session storage. Active workers, uncertain operations, checkpoint findings and spent repair/model allowances remain safety obligations. Load conditional coordination/recovery before unsafe replacement/retry; retain the two-cycle automatic delivery-repair ceiling and applicable restrictions. New sessions and renamed findings reset nothing.

Discover actual needed companions, inspect complete entries and relevant references, and verify semantic compatibility/source identity. Resolve relative targets from their containing package; recover truncated reads before acting. Missing helpers block their dependent route without installation or legacy substitution. Return actual complete/partial/blocked outcomes, evidence/limits and next action. Separate acceptance, publication, merge and release.
<!-- end:agreement -->

<!-- surface:setup -->
### Setup responsibility

On explicit setup, inspect existing instructions, state, authoritative homes and selected local/remote route without mutation. Map context, decision/effect authority, verification/review, documentation/domain maintenance and evidence/continuation responsibilities to useful existing guidance or proposed files. Empty glossary/ADR/tracker artifacts are unnecessary.

Resolve actual missing decisions in manageable ordered rounds. Preserve customizations, restrictions and confirmed answers. Reconciliation compares semantic responsibilities, not filenames or hashes; unchanged compatible guidance produces no substantive edits. Ask about consequential policy changes, not routine engineering seams. Explain optional assessment choices separately from ordinary agent work; load model-use detail only for relevant permission discovery/proposals and make no service calls. Load tracker, release, domain or GitHub procedures only for the selected operations. Existing/interrupted setup loads reconciliation before edits.

Obtain final approval of exact cumulative effects; recheck affected state, apply scoped changes through their owners, and read back each result. Preserve successful independent effects on partial failure; inspect uncertain remote state before retry. Verify entry links, meaningful content and no substantive rerun delta. Return verified, omitted, deferred and blocked operations without starting application work or backlog creation.
<!-- end:setup -->

<!-- surface:shape -->
### Shaping responsibility

Bound the outcome, users, decision owner, existing agreements and exclusions. Reuse confirmed decisions and inspect discoverable facts. Ask about relevant intent in manageable rounds, following answer-driven branches across goals, workflows, exceptions, constraints and consequential trade-offs. Cover the whole requested set of people/items/cases rather than merely shared rules. Record required, deferred, excluded and accepted-limitation dispositions with rationale and necessary approval; a round bound yields an honest incomplete result, not invented agreement.

Resolve agreement-critical technical uncertainty through bounded Analyze within existing inspection authority before confirmation; use Research or Domain Modeling only for actual gaps. Distinguish implementation-only later analysis and its revisit condition. Inspect specialist evidence and resume this responsibility without making the user coordinate internal steps.

Check the proposed workflow against a representative example and material exception. Present a usable plan for confirmation when all material intent and evidence gaps are resolved; corrections reopen affected questions only. A current already confirmed plan needs no ceremonial reapproval. Return explicit shaping-complete/partial/blocked status and dispositions. Confirmation completes shaping without requiring specs/tickets or executing the recommended next stage.
<!-- end:shape -->

<!-- surface:analyze -->
### Analysis responsibility

Bound the technical question against supplied agreement, current implementation/callers, ownership, coverage and environment. Compare deciding identities, including relevant dirty state, before reusing findings. Inspect sources and assertions, not names/counts; fill only material gaps. Use source research or plan-only/approved domain work when needed and inspect the returned support.

Recommend the smallest adequate design and method/check strategy, with risks, interfaces, protected scope, dependencies and documentation disposition. Challenge speculative complexity without weakening safety or domain rules. Inspect relevant candidate capabilities before describing availability; an unavailable method blocks execution, not a justified recommendation. Technical lead chooses routine methods and seams, while consequential commitments require their owner.

Return supported readiness, actual baseline evidence versus planned/unrun checks, current/stale findings, remaining deciding gaps and next action. No build, publication or acceptance gate is established by this analysis alone.
<!-- end:analyze -->

<!-- surface:investigate -->
### Investigation responsibility

Bound expected/actual behavior, impact, environment, contract source and diagnostic effects. Inspect prior reproduction/cause evidence against deciding code, callers, tests and configuration, including dirty state. Reuse current evidence; source mentions do not authorize a fix. Set finite attempts/time and stop conditions.

Reproduce safely at the smallest representative boundary. Record commands/inputs, expected versus actual results, versions, intermittent attempts and limits. Harness/permission failures do not confirm a bug. Trace the causal path with discriminating observations, separating hypotheses from established cause. Inspect technical/source gaps through their owners only when needed. Do not change expected behavior without the proper decision.

Account for owned probes and permitted cleanup, preserving intervening/unrelated work. Return diagnosis with impact, reproduction, causal evidence, affected sources, bounded fix/exclusions/dependencies/risks, regression criteria and method recommendation. Unconfirmed symptom or unresolved cause stays investigation-only with the next bounded evidence action. Ticket-ready diagnosis can complete in conversation without tracker access, Write Tickets or publication. Recommend direct delivery or tickets when appropriate without starting either. Explicit investigation-and-fix returns complete current diagnosis to the authorized delivery lead; this procedure itself ships no fix.
<!-- end:investigate -->

<!-- surface:work-on -->
### Single-change responsibility

Confirm one explicitly requested bounded delivery, approved effects, acceptance and current readiness. Inspect actual branch/base/PR and committed/index/working/untracked state; preserve unrelated ownership/history. Raw bugs use only missing diagnosis; complete current investigation can be conversation input without a ticket. Missing agreement-critical facts block affected building; do not manufacture phases or ask engineering questionnaires.

Use Preflight before Git writes. Select the smallest useful method from current evidence and binding policy, inspect its actual capability and returned local evidence. Methods own their loops. Invoke domain/source/analysis owners only for real gaps. Ordinary direct work needs no worker ledger; delegation loads conditional coordination and reserves root ownership/bounds. Verification maps all acceptance and material risks to actual integrated-state evidence. Review pins full dirty scope/supporting inputs and supplies independent neutral Standards/Spec contexts. Missing material checks or independence blocks acceptance.

Disposition findings through completion, preserving lineage, two-cycle allowance and prior reports. Refresh affected checks and significant-change review after repairs. Record build, acceptance recommendation and report separately; documentation impact and partial/blocked results remain visible. Return implemented/verified/unverified/deferred/blocked scope and actual artifacts, with PR-ready only when supported. Do not run PR or create a handoff merely because delivery finished. A user-selected PR request later reuses current evidence.
<!-- end:work-on -->

<!-- surface:work-on-spec -->
### Whole-spec responsibility

Confirm explicit overall delivery, approved spec/tickets, native graph, accepted prerequisite integration, current state and protected work. Use the existing root record; ordinary ticket evidence is reused after deciding-input checks. Conditional coordination is required for actual workers; writable bounded assignments and inspectable lifecycle/results are necessary, not an inspect-only substitute.

Dispatch owns native eligibility/frontier, exclusive scopes/interfaces, lead-chosen concurrency and rolling scheduling. Ticket leads use bounded Work On and request additional allocations from the root; no recursive pools. Inspect each return and integrate serially under project policy. Required predecessor PR/merge permission remains a stage blocker until selected/approved, never implicit publication.

Aggregate acceptance maps the whole agreement and cross-ticket risks to integrated evidence; child passes are insufficient. Supply current snapshot/checks to independent aggregate review. Preserve local finding lineage and spent allowances; genuinely new cross-ticket findings use the integrated checkpoint. Recovery reconciles uncertain owners, operations and budgets before retries. Return per-ticket and overall implemented/integrated/verified/unverified/blocked scope and distinct gates. Stop before unrequested PR/persistence/merge/release.
<!-- end:work-on-spec -->

<!-- surface:coordination -->
### Conditional coordination responsibility

The root alone reserves and launches authorized bounded assignments. Record owner/identity, exact scope/interfaces, effects, isolation, finite runtime, state/evidence references and expected return. Choose useful concurrency from eligible work, resources, review demand and explicit restrictions; no invented ceiling or batch barrier. Submitted unfinished or uncertain workers retain ownership/capacity until confirmed stopped or isolated. Ticket workers request root allocations rather than recursively delegate.

Concurrent writes need exclusive scope and stable interfaces; integrate serially. Freeze reviewed scope/supporting inputs or use an authorized complete immutable snapshot. Reviewers stay read-only and independent of authors and each other's conclusions. Missing authority/capability blocks that route; equivalent direct work is permitted only where it preserves the required outcome, never as independent self-review or silent whole-spec direct execution.

On interruption/failure, preserve artifacts and inspect actual lifecycle/remote outcomes before replacement or retry. Retain finding/checkpoint and attempted-model history; transfer/resume cannot reset allowances. Use responsible lead recovery for uncertainty, completion for repair counting and the exact model policy/named assessment for authorized allocations. This live safety record does not create a generic durable session report or authorize disclosure, installation or service operations.
<!-- end:coordination -->

## Reproducible counter

Run the following Python 3 block from the repository root, extracting it to temporary storage if convenient. It reads Git objects and this document only, creates no repository files and performs no network/model actions. The complete manifests and per-context subtotals are printed for inspection. Keep reviewer totals rather than subtracting them to make delivery look cheaper.

```python
from pathlib import Path
import subprocess

REV = "45e5a24"
doc = Path("docs/design/session-oriented-reading-paths.md").read_text()
def words(text):
    return len(text.split())
def baseline(path):
    return subprocess.check_output(["git", "show", f"{REV}:{path}"]).decode()
def surface(name):
    return doc.split(f"<!-- surface:{name} -->", 1)[1].split(
        f"<!-- end:{name} -->", 1)[0]
def entry(name):
    return f"workflow/{name}/SKILL.md"
def ref(name, file):
    return f"workflow/{name}/references/{file}.md"
def total(paths):
    return sum(words(baseline(p)) for p in sorted(set(paths)))

project = ["AGENTS.md", "docs/agents/project.md", "docs/agents/workflow.md"]
tracker_policy = ["docs/agents/issue-tracker.md", "docs/agents/triage-labels.md"]
tracker = [entry("setup-project"), ref("setup-project", "issue-tracker")]
review = [entry("review-delivery")] + [ref("review-delivery", n)
    for n in ["handoff", "scope", "report"]]
lead = [entry("work-on"), ref("work-on", "contracts")]
local = [ref("work-on", n) for n in ["build", "verification", "completion"]]
method = [entry("implementation-preflight"), entry("build-and-check")]
pr = [entry("pr"), ref("pr", "impact"), ref("pr", "publication")]
setup = [entry("setup-project")] + [ref("setup-project", n) for n in
    ["documentation-contract", "discovery", "model-use", "releases"]]
# Each tuple: context name, baseline files, proposed retained files,
# proposed design surfaces, contextual project additions (both columns).
review_context = lambda n: (n, review, review, ["agreement"], [])
bounded = ("lead", lead + local + method + review + pr,
           local + method + review, ["agreement", "work-on", "coordination"], [])
whole_refs = [entry("work-on-spec"), ref("work-on-spec", "dispatch"),
              ref("work-on-spec", "aggregate")]
scenarios = {
    "setup": [("setup", setup, [ref("setup-project", "releases")],
               ["agreement", "setup"], [])],
    "planning": [("planner", [entry(n) for n in
        ["shape-work", "analyze", "build-and-check"]],
        [entry("build-and-check")], ["agreement", "shape", "analyze"], [])],
    "investigation": [("investigator", [entry("investigate-bug"),
        entry("write-tickets")] + tracker, [],
        ["agreement", "investigate"], [])],
    "bounded": [bounded, review_context("standards"), review_context("spec")],
    "whole-spec": [
        ("root", whole_refs + lead + local[1:] + tracker + review + pr,
         whole_refs[1:] + local[1:] + tracker + review,
         ["agreement", "work-on-spec", "coordination"], tracker_policy),
        ("ticket", bounded[1] + tracker, bounded[2] + tracker,
         bounded[3], tracker_policy),
        review_context("ticket-standards"), review_context("ticket-spec"),
        review_context("aggregate-standards"), review_context("aggregate-spec")],
}
for name, contexts in scenarios.items():
    bsum = psum = shared = 0
    for label, before, retained, sketches, extra in contexts:
        # Investigation's proposed branch needs no tracker project docs.
        b_extra = tracker_policy if name == "investigation" else extra
        p_extra = extra
        b = total(before) + total(b_extra)
        p = total(retained) + sum(words(surface(n)) for n in sketches) + total(p_extra)
        common = total(project)
        bsum += b; psum += p; shared += common
        print(name, label, "baseline", b, "proposed-sketch", p,
              "project", common, "baseline-files", sorted(set(before + b_extra)),
              "retained", sorted(set(retained + p_extra)), "surfaces", sketches)
    print("TOTAL", name, "package+branch-guidance", bsum, psum,
          "including-fixed-project-guidance", bsum + shared, psum + shared)
```

### Interpretation and follow-up

The executable manifest is a conservative design comparison: proposed delivery retains the **entire current** build/verification/completion, review, tracker and dispatch/aggregate files even where later implementation will reconcile their legacy pointers. Those transitive pointers are replaced by the ownership contract/sketches, not recursively loaded as old instructions in the proposed model. This models the intended dependency graph, not a runnable mixed-version installation. Do not use these columns to claim that the currently shipped files already follow that graph.

The sketches add the common agreement in every proposed context while the fixed actual project guidance remains counted too, deliberately overcounting common policy rather than attributing savings to a smaller fixture. They do not account for the eventual full metadata/local failure-case text. Reductions identify where reading can be removed or made conditional; they are not a word budget for implementers. Review/worker costs can dominate a real session and must be measured after implementation. Setup's lower proposed load does not mean necessary interview decisions can be skipped.
