# Overall delivery recovery

Read completely before resuming interrupted/failed spec delivery or when graph, worker ownership, integration outcomes, evidence or ledger history are uncertain. Resolve and read Work On's `references/recovery.md` as the local artifact/operation reconciliation library, plus its execution contract, without invoking the single-change entry. This procedure owns the additional graph/frontier/integration/worker reconstruction; no new authority or persistence service follows from recovery.

## 1. Reconstruct actual overall state

Inspect the current agreement, authority, approved durable record and deciding companion sources. Use the local recovery library for actual branches/worktrees, dirty files, protected work, conflicts, uncertain commits/pushes/PR effects, check/reviewer returns and checkpoint history. Apply it to each relevant local artifact and overall integrated target. Retain source artifacts and original evidence; summaries/labels are discovery pointers, not proof.

Re-read native relationships through the discovered maintained tracker library, including both directions, pagination, external prerequisites and parent ancestry. Compare intended and observed graph, current role/readiness mappings and accepted integration evidence. Failed reads remain unknown; closed prerequisites without target-required accepted integration leave dependents waiting. Return exact graph deltas through discovered Write Tickets for approval/read-back rather than mutating implicitly.

Inspect actual assignment identity, scope/isolation, lifecycle and finite bounds against the root ledger. A session crash or timeout report alone does not free a slot/owner. Reconstruct submitted unfinished workers, including idle and review assignments; reconcile stopped/isolated states before replacement. Recover exclusive interface reservations, integrated/not-integrated ticket states, local and final checkpoint lineage/counts, model reservations/attempted or unknown usage and uncertain operations. Missing history blocks dependent automatic correction/calls, not read-only diagnosis.

**Done:** every ticket/artifact, prerequisite, active reservation, operation and budget has observed state or explicit uncertainty, with protected work and evidence pointers retained.

## 2. Reconcile effects before reclaiming ownership

Use the local recovery library's inspect-before-retry dispositions for each uncertain operation. In particular, inspect actual target refs, diffs/source presence and PR/merge policy evidence before retrying integration. Ancestry can establish a merge; squash/cherry-pick needs inspected content equivalence and acceptance evidence. Already applied work is recorded, never blindly reapplied. Partial/conflicting/unknown outcomes block dependent actions and retain both sides; no implicit abort/reset/cleanup.

Confirm prior writers stopped or are isolated from replacement scope before reclaiming reservations. Budget and model allowance follow the unresolved cause/run, not the replacement worker, ticket name or session. Further correction after exhaustion requires an explicitly approved revised plan/budget; uncertain charge/reservation blocks dependent sends. Optional models never substitute for reconstructed facts or independent review.

**Done:** actual integrated effects and lifecycle are reconciled or blocked, and every proposed launch/write has exclusive ownership, current authority and preserved available allowance.

## 3. Recompute the frontier, not the old launch list

Compare current agreement, integrated target and complete dirty/supporting-input identities with retained checks/review. Mark dependent evidence stale, keeping historical results. Integrated work with missing evidence goes to [aggregate acceptance](aggregate.md), not duplicate building/integration. Pending required merges keep dependents waiting even if an aggregate staging branch contains the source.

Return reconstructed state to [dispatch](dispatch.md) to recompute the ready frontier and combined ownership/capacity. Refresh actual prerequisite evidence before launches. Unaffected eligible work may progress through bounded Work On agents when safe; an unavailable writable runtime leaves execution blocked with a useful plan. Resume the earliest unmet responsibility, preserving settled local decisions and cross-ticket lead ownership. Freeze writes/integration during verification/review; refresh significant-change review after corrections.

**Done:** each ticket is retained/integrated, eligible for one justified responsibility, waiting or blocked with reason/owner; no launch list or spent allowance is blindly replayed.

## 4. Retain and return recovery evidence

Update the approved record with graph observations, actual refs/snapshots, retained artifacts, active/stopped/uncertain workers, resolved/unknown operations, checkpoint/finding/model history, stale/refreshed evidence and the selected next frontier/gate. Multi-session unfinished work needs an approved durable pointer under retention/disclosure policy; if unavailable, disclose the recovery limitation rather than publish private logs or invent a committed state directory.

Cleanup remains separately authorized after inspecting unique commits, dirty/untracked content, active owners and evidence pointers. Preserve useful branches/worktrees and failed outputs otherwise. Return retained, verified, actually resumed and blocked scope with owner/evidence/next action. A selected handoff is not resumed execution; successful recovery is not aggregate acceptance, merge or deployment.

**Recovery completion:** a justified next responsibility actually resumes, or precise preserved blockers and accessible pointers enable the next authorized lead to reconstruct the run without duplicating effects or resetting shared limits.
