# Validate GitHub setup guidance

Validate offline before any separately authorized disposable live test. This package has no automated repository-creation test; do not pretend a command sketch is an executed GitHub workflow.

1. Read the full skill and handoff reference. Check frontmatter and relative links.
2. Walk the create-new standalone route: exact approved target/files/settings, missing auth, missing first commit, and protected refs.
3. Walk configure-existing: custom visibility, Projects/Discussions/Wikis, labels, files, remotes, rules, and organization constraints survive unless specifically approved to change.
4. Walk plan-only and approved handoffs: no mutation before approval; no repeated resolved questions; changed scope returns for approval.
5. Simulate unavailable baseline permissions/features and ambiguous 404s: result is blocked/unverified, not disabled/absent or silently weakened.
6. Walk partial creation and rerun: inspect current state, skip satisfied actions, preserve unrelated changes, and report uncertain operations.
7. Verify command syntax against installed `gh ... --help` and current GitHub documentation where needed. Real setting mutations require separate approval of a disposable target and action scope.

The companion setup-project package contains offline packaging checks, native dependency helper tests, and a broader manual scenario matrix. That package is not required for standalone use here.
